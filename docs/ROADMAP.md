# Development Roadmap

This document defines the frozen, sequential 26-phase development roadmap for the **CoinDCX Quant Futures Bot**. Each phase builds deterministically upon the foundations established by preceding phases.

---

| Phase | Name | Description | Status |
| :--- | :--- | :--- | :--- |
| **Phase 0** | **Frozen Documentation** | Establish core architectural source of truth, scope boundaries, invariants, onboarding procedures, and strategy lifecycle. | COMPLETE |
| **Phase 1** | **Foundation** | Node.js + strict TypeScript setup, Express server, MySQL 8 + Prisma persistence, Zod configuration, decimal arithmetic, structured logging with secret redaction, health API, graceful shutdown, Vitest, Docker, and GitHub Actions CI. | COMPLETE |
| **Phase 2** | **CoinDCX Read Layer** | Read-only REST API client for CoinDCX: instrument metadata discovery, contract specifications, order book snapshots, historical trade queries, and rate-limit tracking. | COMPLETE |
| **Phase 3** | **Coin Runtime Layer** | Dynamic, isolated per-coin operational supervisor; coin configuration loading without hardcoded symbol logic. | COMPLETE |

| **Phase 4** | **Public/Private WebSockets** | Real-time WebSocket connection manager: public trade feeds, order book depth feeds, private user execution updates, automatic reconnection, and heartbeat management. | COMPLETE |
| **Phase 5** | **Canonical 1m Market Data** | Transport 1m candle update -> canonical 1m finalization, successor-confirmed finality, gap detection, REST recovery barrier, and immutable persistence of finalized 1-minute OHLCV candles to MySQL 8. | COMPLETE |
| **Phase 6** | **Generic Higher-Timeframe Engine** | Pure mathematical aggregation engine deriving generic higher-timeframe candles (initial supported set: 2m, 3m, 4m, 5m, 10m, 15m, 30m, 1h, 4h, 1d; safe integer `timeframeMinutes >= 2`) exclusively from canonical 1m data with exact completeness, isolated 64-bit decimal arithmetic, pair-scoped serialization, and deterministic batch/live parity. | COMPLETE |
| **Phase 7** | **Historical Dataset Engine** | Deterministic, reproducible historical canonical 1m dataset engine: resumable chunked REST backfill via CoinDcxFuturesCandleRestReader, zero synthetic gap-filling, immutable MySQL candles_1m persistence, deterministic SHA-256 content/datasetId hashing, manifest tracking, streaming NDJSON export/import, and Phase 6 higher-timeframe parity. | COMPLETE |
| **Phase 8** | **Indicator Engine** | Deterministic technical-indicator computation engine (SMA, EMA, Wilder RMA, ATR, RSI, MACD, Bollinger Bands, DMI/ADX, SuperTrend, Donchian Channel, UTC-day VWAP, Volume SMA, Volume Ratio) operating on validated closed candles with strict 128-digit isolated decimal precision, dual incremental/batch parity, zero lookahead, and deterministic warmup alignment; true Volume Profile is explicitly deferred pending canonical trade-level price-volume data. | COMPLETE |
| **Phase 9** | **Backtest Engine Foundation** | Deterministic, reproducible, event-driven backtest simulation engine operating strictly on verified Phase 7 canonical 1m datasets: two-pass cryptographic dataset binding, exact Phase 6 higher-timeframe and Phase 8 indicator kernel reuse, causal next-bar event loop with cancellation causality, conservative OHLCV execution semantics (all-or-none fills, raw-open post-only rejection, resting strict penetration, gap-through stop-market, intrabar OCO adverse-first with global sequence total ordering, whole-order reduce-only excess rejection), exact reversal accounting on closing quantity, deterministic accounting ledger, explicit fees, spread/slippage attribution, causal funding boundaries, immutable input snapshot, maxOpenOrders in run identity, terminal open orders reporting, fail-closed sink failure, and deterministic SHA-256 run/ledger/result hashing. | COMPLETE |
| **Phase 10** | **Strategy Framework & First 4 Strategies** | Environment-neutral quantitative strategy framework, deterministic strategy identity and canonical parameter hashing (parameterHash, strategyInstanceId), discriminated non-actionable warmup state model (WARMING vs. READY), abstract target-exposure decisions (LONG, SHORT, FLAT), exact trigger-timeframe scheduling, same-timestamp multi-timeframe synchronization, Phase 8 indicator kernel reuse, first four parameterized strategies (EMA Trend, ATR Breakout, RSI Momentum, Multi-Timeframe Trend), and thin Phase 9 research backtest adapter. | COMPLETE |
| **Phase 11** | **Strategy × Coin Matrix & Parameter Research** | Deterministic Strategy × Coin Matrix and parameter research engine: predeclared finite candidate space expansion (lexicographical dimension sorting, Cartesian cell generation), input-side defensive deep-freeze, Phase 10 parameter validation authority, explicit duplicate parameter candidate rejection, versioned indicator bootstrap policy (P11_INDICATOR_BOOTSTRAP_V1 for EMA, ATR, RSI with exact 3x period warmup and multi-timeframe common origin alignment), verified clean Git source contract (auto-captured full commit OID, clean tree enforcement, mid-run invalidation safety), authoritative Phase 9 manifest and runId construction path, absolute Phase 9 BacktestEngine and Phase 10 StrategyKernel environment parity, fixed nominal research quantity binding, cryptographic lineage (matrixPlanId, matrixCellId, matrixResultSha256), canonical cell sequence total ordering, concurrency-invariant multi-worker execution with zero wall-clock canonical contamination, discriminated terminal results (COMPLETED with BacktestRunResult vs FAILED with MatrixCellFailure), tamper-proof Phase 9 completed-result cache verification, fail-closed error hierarchy, and strict read-only research boundary (zero ranking, zero live mutation). | COMPLETE |
| **Phase 12** | **Research Validation Lab** | Deterministic statistical robustness validation suite evaluating frozen Phase 11 candidate spaces: cryptographic validation plan identity (`validationPlanId`), cross-fold subject identity (`validationSubjectId`), chronological walk-forward analysis (`P12_WALK_FORWARD_V1`) with non-overlapping OOS test windows, final holdout isolation with operator attestation, streaming event evidence collection with independent event ledger hashing and structural cache exclusion bound to Phase 9 `runId`, `resultSha256`, and `eventLedgerSha256`, UTC daily terminal equity tracking ($N$ returns from $N+1$ boundaries) with funding-edge resolution, 128-digit isolated decimal financial metrics (Sharpe, Sortino, minute-close max drawdown, net daily returns, gross trade vs net daily profit factor and expectancy), discriminated validity states (`VALUE`, `UNDEFINED`, `INSUFFICIENT_DATA`; zero `NaN`/`Infinity`), multi-scenario real Phase 9 cost stress testing, deterministic Monte Carlo permutation testing (`P12_MONTE_CARLO_PERMUTATION_V1` via HMAC-SHA256 PRNG), multiple-testing overfitting control (Deflated Sharpe Ratio with $M=1$ branch, IS $\to$ OOS degradation, OOS consistency), generic parameter neighborhood sensitivity, fail-closed approval policy (`PASSED`, `FAILED`, `INSUFFICIENT_EVIDENCE`), and strict non-ranking boundary (Phase 15 owns ranking). | COMPLETE |
| **Phase 13** | **Risk + Leverage Engine** | Deterministic, non-bypassable Risk / Leverage Engine turning a genuine Phase 10 `StrategyDecision` (status=READY only; WARMING is a structural no-op) into a discriminated, auditable `RiskDecision` (`AcceptedOpenRiskDecision \| AcceptedCloseRiskDecision \| RejectedRiskDecision`, approved fields never populated on a rejection, each accepted action shaped only for the fields it actually computes): action derived deterministically from `targetExposure` + current position (`OPEN`/`CLOSE`/`NO_CHANGE`/`REVERSAL_DEFERRED`, no partial-reduce or atomic reversal in V1), with ownership (a per-instance record binding the complete `strategyInstanceId` + `strategyId` + `strategyVersion` + `parameterHash` tuple — never `strategyInstanceId` alone — plus current quantity, current notional, and bound `pair`/`accountId`, represented as a discriminated flat-vs-open union that never fabricates a `positionId` for a flat pair and requires a genuine one for an open position) failing closed for **both** `OPEN` and `CLOSE` when unreconciled or when reported quantities **or reported current INR notionals** fail aggregate reconciliation — notional being derived by one frozen, policy-versioned valuation method (mark price × contract multiplier × settlement conversion rate, quantized once into a shared per-unit factor), recomputed by the engine rather than trusted, compared under exact tolerance-free canonical-Decimal equality, and unreconciled rather than substituted whenever mark price is unavailable; CoinDCX's signed position quantity is normalized to a `positionDirection` label plus a strictly-positive `quantityMagnitude` at one frozen boundary, after which every per-instance quantity is a strictly-positive magnitude (zero shares omitted, never a `"0"` entry) with direction inherited from the open position and never encoded in a quantity's sign, making mixed-sign cancellation structurally impossible in `RECONCILED` state — new exposure is never authorized against a pair whose existing attribution cannot be proven, and `CLOSE` is authorized only for the requesting instance's proven owned share, never by `strategyId` or `strategyInstanceId` alone; entry/stop/leverage supplied as separate, versioned, provenance-bound proposals never fabricated onto the strategy decision; a field-by-field authority matrix (`PROPOSE`/`TIGHTEN`/`HARD_CAP`/`NOT_APPLICABLE`, never `Infinity`) across global config → pair config → risk mode → per-trade override → CoinDCX dynamic tiers → account/exposure state; conservative risk-budget position sizing with floor-only quantization feeding a first-class `PositionSizingDecision`; a finite, single-pass leverage-tier enumeration over adapter-verified explicit tier intervals that intersects every applicable notional cap (instrument `maxNotional`, resolved max-notional-per-trade, exposure headroom — not just margin) and selects the true greatest feasible quantity across every tier (no fixed-point loop); initial-margin-only financial reporting with maintenance margin/liquidation price explicitly deferred; policy-owned (never snapshot-declared), zero-clock-skew-tolerance freshness and causal ordering gated against `RiskEvaluationContext.evaluationTimeMs`, with position identity (`positionId`) preventing stale ownership reuse across a closed-and-reopened position and every snapshot's `sourceId` independently checked against a policy-owned expected-source-authority contract; gross-notional exposure limits with discriminated KNOWN/UNKNOWN pending exposure; UTC-day realized-only daily-loss gated primarily by direct comparison against a required, strictly positive, resolved INR cap (a percentage-of-equity variant remains available only as a separate, optional secondary gate, never a substitute) and equity-inclusive drawdown circuit breakers; a two-universe rejection taxonomy with one unambiguous rule per condition (malformed evidence preventing canonical identity throws `RISK_SOURCE_INVALID`; once identity exists that code is unreachable; unexpected source authority uses `SOURCE_ID_MISMATCH`, declared identity/content-hash disagreement uses `DECISION_IDENTITY_MISMATCH`, completed valuation-value disagreement uses `POSITION_OWNERSHIP_UNRECONCILED`, valuation context exhaustion uses `VALUATION_NUMERIC_CONTEXT_EXCEEDED`, and method mismatch uses `VALUATION_METHOD_MISMATCH`) and a frozen 13-step evaluation pipeline whose within-step reason ordering is resolved by one canonical, self-validating global precedence table (every rejection code exactly once, never incidental iteration order); deterministic `riskPolicyId`/`positionSizingDecisionId`/`riskDecisionId` identity via the existing canonical-JSON hasher with canonical decimal normalization (every outcome-affecting policy layer bound in, freshness thresholds included via `riskFreshnessPolicyId`, so no max-age change can alter results under an unchanged identity), an accepted `OPEN` approval that is a pure value-preserving seven-field projection of the authoritative `PositionSizingDecision.sizing` record rather than a structural duplicate of it; and an explicit invariant that an `ACCEPTED` decision is scoped to its bound evidence and is never valid forever. Account-equity, tier-semantics, and settlement-conversion (bound to an explicit market identity, not currencies alone) adapters are frozen as interfaces only (none exist in Phase 2 today). Explicitly excludes live order placement, `ExecutionIntent`, `InstrumentSelectionDecision`, paper execution, and ranking. | CURRENT |
